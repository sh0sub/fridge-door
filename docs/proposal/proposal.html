Fridge Door

Uliya Skill for UGREEN AI NAS · UGREEN Hackathon 2026, Round 1 proposal

1. What does your Skill do?

Fridge Door reads the school notices and children's drawings that sit as photos on the NAS and turns them into a weekly parent to-do digest and per-child artwork albums, entirely on the device.

2. Target user and problem

Parents of kindergarten and primary-school children who photograph paper notices and artwork. The photos sit forgotten in a backup folder: reply slips and fees are missed, and hundreds of drawings cannot be attributed or found. Parents who do not read the local language are hit hardest.

3. Solution

Once a week the parent asks Uliya. The Skill lists the period's photos, reads each with on-device OCR, structures notices into deadline, action, amount and child, and checks picture-only photos with the on-device vision model. After one confirmation it creates albums in UGREEN Photos and saves a digest file. Tagged photos are skipped next time.

4. Main user flow

"Sort out this week's school papers" → confirm folder, period, children → OCR and vision per photo → preview of deadlines, events, artwork and planned creations → approve → albums, digest, tags → report with the next due item and source file names.

5. Differentiation

Album tools organize pictures; Fridge Door turns pictures into actions with dates. It attributes artwork by reading the child's name written on it, translates notice summaries for non-native parents, and uses NAS file tags as run memory. Nothing leaves the NAS.

6. NAS features used

Step 1 ug-filesystem find (file-agent); Steps 2 and 9 ug-filemgr tag lookup and tag-add-file (file-agent); Steps 3–4 ug-photo vision-ocr, vision-vlm (photo-agent); Step 5 ug-document writing and translate --content (document-agent); Step 7 ug-photo create-album (photo-agent); Step 8 ug-knowledge save-text (knowledge-agent).

7. Technical approach

A Markdown orchestration Skill: the parent issues only delegate commands to four registered experts in fixed order, passing only real upstream results. Originals are only read, except an optional archive step, off by default, run on explicit request. Other writes are albums, one digest file and a tag, each after confirmation and platform approval. Only built-in NAS models; no external services or keys. All five delegation states, empty and partial results are handled; runs are capped at 12 photos.

8. Progress

Built: complete Skill package passing the official static checker with zero errors and warnings; 115 automated tests with dry runs on simulated expert answers; a 16-photo invented test kit specification. Needs NAS testing: OCR on Korean and English print, vision on drawings, album creation from file paths, approval wording.

9. Finalist test plan

Core 1: eight notices yield six deadlines in date order, one flagged past, plus two events, each citing its photo. Core 2: six drawings yield per-child albums, two assigned from names read on them, the rest by the parent's answer; a second run skips all thirteen handled photos. Edge: a blurred drawing and a receipt are reported as unreadable and unrelated; nothing is invented or created before confirmation.

10. Limits, risks, dependencies

Images only; handwritten notices and poor light reduce OCR quality and are reported, not guessed. Twelve photos per run. Child attribution needs the name on the artwork or the parent's answer. Depends entirely on built-in NAS experts; translation quality follows the on-device model.

Team: individual.

Third-party components: none. Only the OCR, vision, document and translation models built into the NAS; no external service or API key.
