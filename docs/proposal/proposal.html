Fridge Door

Uliya Skill for UGREEN AI NAS · Round 1 proposal

1. What does your Skill do?

Fridge Door turns school-notice and children's-drawing photos on the NAS into a weekly parent to-do digest and per-child artwork albums, entirely on the device.

2. Target user and problem

Parents of kindergarten and primary-school children who photograph paper notices and artwork, then forget the photos. Illustrative estimate: two children, three notices a week, about 100 deadlines per school year, each a photo nobody reopens. Reply slips and fees get missed, especially by parents who do not read the local language.

3. Solution

Weekly, the parent asks Uliya. The Skill lists the period's photos, reads them with on-device OCR, structures notices into deadline, action, amount and child, and checks picture-only photos with the vision model. After one confirmation it creates albums and a digest file; tagged photos are skipped next time.

4. Main user flow

"Sort out this week's school papers" → confirm folder, period, children → OCR and vision → preview → approve → albums, digest, tags → report with next due item and source file names.

5. Differentiation

Album tools organize pictures; Fridge Door turns them into dated actions. It attributes artwork by the child's written name, translates summaries for non-native parents, and uses NAS file tags as run memory. Nothing leaves the NAS.

6. NAS features used

ug-filesystem find, ug-filemgr tags; ug-photo vision-ocr, vision-vlm, create-album; ug-document translate; ug-knowledge save-text.

7. Technical approach

A Markdown orchestration Skill: the parent issues only delegate commands to four registered experts in fixed order, passing only real upstream results. Originals are only read unless archiving is requested. Albums, one digest file and a tag are written after confirmation and platform approval. Built-in models only; no keys. All five delegation states and empty or partial results are handled; 12 photos per run.

8. Progress

Checkable now: 123 automated tests with dry runs on simulated expert answers; zero errors and warnings from a local port of the official checker rules; a 16-photo invented test kit with expected results. Not yet run on a NAS: OCR on Korean print, vision on drawings, album creation.

9. Finalist test plan

Core 1: eight notices yield six deadlines in date order, one flagged past, plus two events, each citing its photo. Core 2: six drawings yield per-child albums; a second run skips all thirteen handled photos. Edge: a blurred drawing and a receipt are reported, not handled; nothing is created before confirmation.

10. Limits, risks, dependencies

Images only; handwriting and poor light reduce OCR quality and are reported, not guessed. Twelve photos per run. Attribution needs the name on the artwork or the parent's answer. Depends on built-in NAS experts.

Team: individual. Third-party components: none. AI tools: Claude Code (Anthropic) helped draft the Skill, proposal and checks; uliya-skill-kit 0.7.3 was the reference.
